What you are deploying

Matches docker-compose.yml · five containers

The Compose file runs api (FastAPI / Uvicorn on port 8000), streamlit (UI on 8501, API_URL=http://api:8000), and internal-only postgres, redis, and chromadb. Postgres, Redis, and Chroma are not published to the host. Chat is Server-Sent Events at /api/v1/chat/stream. Health checks: GET /api/v1/health/live and GET /api/v1/health/ready.

HITL constraint LangGraph uses in-process MemorySaver. Approval resume lives in that API process. Multiple API replicas break HITL unless you add session affinity or switch to a Postgres checkpointer (not in this repo yet). Keep one API replica on a single VM and in the scalable designs below. Chroma is also stateful: run one instance, not N independent Chromas.

Shared prerequisites

Every cloud · every topology

  • Docker Engine and the Compose plugin on the host (or a platform that runs the same images).
  • A filled .env from .env.example: OPENAI_API_KEY (and optional ANTHROPIC_API_KEY), a long random JWT_SECRET, a strong POSTGRES_PASSWORD, ENVIRONMENT=production.
  • CORS_ALLOWED_ORIGINS set to the public UI origin (for example https://ui.example.com). Streamlit is server-to-server and does not rely on CORS.
  • TLS in front of Streamlit and the API. Do not leave 8000/8501 on the public internet without a proxy.
  • Firewall: public 80/443 (and SSH or SSM from your IP). Never publish 5432, 6379, or Chroma.

Local Compose bind-mounts .:/app and runs Uvicorn with --reload. Drop both for a real deploy — the Dockerfiles already copy the application into the image.

Start here: simple EC2

Default path · Ubuntu 22.04 or Amazon Linux 2023 · t3.large

Put all five containers on one instance. Size: about 2 vCPU / 8 GB RAM (t3.large or similar) is a practical floor for API + Streamlit + Postgres + Chroma. Attach enough EBS for Docker volumes (20 GB gp3 is a starting point).

1. Instance and network

  1. Launch Ubuntu 22.04 LTS or Amazon Linux 2023. Assign a public IP (Elastic IP if you want it to survive stop/start).
  2. Security group inbound: 22 from your IP only (skip if you use SSM Session Manager), 80 and 443 from 0.0.0.0/0. No 5432, 6379, 8000, or 8501 from the internet once Caddy is up. During first bring-up you may temporarily open 8000/8501 to your IP for smoke tests.
  3. Optional IAM instance profile with AmazonSSMManagedInstanceCore so you can use Session Manager instead of SSH.

2. Install Docker

Ubuntu 22.04:

sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker $USER
newgrp docker
docker compose version

Amazon Linux 2023:

sudo dnf install -y docker
sudo systemctl enable --now docker
sudo mkdir -p /usr/local/lib/docker/cli-plugins
sudo curl -SL https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64 -o /usr/local/lib/docker/cli-plugins/docker-compose
sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-compose
sudo usermod -aG docker $USER
newgrp docker
docker compose version

3. App files and production Compose

Copy the repository onto the instance (git clone or scp -r). Then cp .env.example .env and edit secrets. On the server, remove the bind mounts and --reload so the baked image is what runs. Example production command for api (no reload) and drop volumes: .:/app on both api and streamlit. Add restart: unless-stopped on every service. 

# .env — production values
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
JWT_SECRET=generate-a-long-random-string
POSTGRES_PASSWORD=strong-unique-password
ENVIRONMENT=production
CORS_ALLOWED_ORIGINS=https://ui.example.com
LANGCHAIN_TRACING_V2=false
# After editing compose: no .:/app mounts, no --reload
docker compose up --build -d
docker compose ps
docker compose logs -f api

On first boot the API still runs alembic upgrade head and scripts/seed.py. With ENVIRONMENT=production, seed refuses to create demo users.

4. TLS with Caddy

Streamlit is awkward behind a path prefix. Use two hostnames (or one hostname plus api. subdomain). Point DNS A records at the Elastic IP. Install Caddy on the host (not in Compose) so it can bind 80/443 and obtain certificates. 

# /etc/caddy/Caddyfile
ui.example.com {
    reverse_proxy 127.0.0.1:8501
}

api.example.com {
    reverse_proxy 127.0.0.1:8000
}

Set Streamlit API_URL=https://api.example.com (the browser and the Streamlit server both call the public API URL unless you keep server-side calls on http://api:8000 and only expose the API for SSE from the UI server). This app’s Streamlit process calls API_URL from the container, so keep API_URL=http://api:8000 for server-side requests. Set CORS_ALLOWED_ORIGINS=https://ui.example.com if a browser ever talks to the API directly.

SSE Caddy’s reverse_proxy does not buffer SSE by default. If you switch to nginx, disable proxy buffering on the API location (proxy_buffering off;, long proxy_read_timeout).

5. First admin and smoke test

POST /api/v1/users requires an admin JWT, so production seed-off leaves a bootstrap gap. Create the first admin inside Postgres, then log in through the UI. 

# One-shot bootstrap: hash a password in the api container, then insert.
# Easier path for a private demo: temporarily set ENVIRONMENT=development,
# restart api so seed.py creates admin@example.com, then set production
# and change that password immediately.

curl -sS https://api.example.com/api/v1/health/live
curl -sS https://api.example.com/api/v1/health/ready
# Open https://ui.example.com — login, send a chat turn, check SSE progress.

Snapshot the EBS volume after a known-good ingest. Named volumes postgres_data and chroma_data live on that disk.

Same Compose on an Azure VM

Delta from the EC2 playbook

Use an Ubuntu 22.04 VM (Standard_D2s_v5 or similar). Follow the EC2 Compose, .env, Caddy, and smoke-test steps unchanged.

  • NSG: SSH from your IP, HTTP/HTTPS from the internet. No data-store ports.
  • Static public IP on the NIC. DNS A records to that IP.
  • Premium SSD OS disk (or a data disk) sized for Docker volumes.
  • Optional: Azure AD SSH login instead of a shared key.

Same Compose on Compute Engine

Delta from the EC2 playbook

Create an e2-standard-2 (or larger) Ubuntu VM. Reuse the EC2 Compose and Caddy steps.

  • VPC firewall: tcp:22 from your IP, tcp:80,443 from the internet.
  • Reserve a static external IP. Point DNS at it.
  • Persistent Disk for the boot volume; snapshots for backup.
  • Optional: OS Login + IAP tunnel instead of a public SSH port.

Scalable architecture

Managed data stores · one API replica · one Chroma

Split the five containers across managed services. Keep API desired count at 1 (or sticky sessions to one task) because of MemorySaver. Keep a single Chroma replica on a persistent volume. Chat SSE needs a long idle timeout and no response buffering on the load balancer.

Shared rollout order on every cloud:

  1. Container registry — build and push Dockerfile.api and Dockerfile.streamlit.
  2. Data stores — Postgres, Redis, Chroma (1 replica + disk).
  3. Secrets — JWT, DB URL, LLM keys, ENVIRONMENT=production.
  4. Compute — UI service + API service (replicas = 1).
  5. Load balancer — TLS, SSE-friendly timeouts, health checks on /api/v1/health/live and /api/v1/health/ready.
  6. DNS — public UI origin in CORS_ALLOWED_ORIGINS; Streamlit API_URL = internal API DNS (for example http://api:8000 on a shared network, or the internal service URL).
  7. Smoke test — live/ready, login, one streamed chat turn, one document upload.

AWS scalable

ALB · ECS Fargate · RDS · ElastiCache · Chroma on EFS

  • ALB target groups: UI :8501 and API :8000. Health: API /api/v1/health/ready. Idle timeout ≥ 120s for SSE. Do not enable response buffering features that hold the stream.
  • ECS services: Streamlit can scale out; API desired count = 1 until a Postgres checkpointer exists.
  • RDS PostgreSQL 15. Point DATABASE_URL at it. Run migrations on API startup (already in the container command) or a one-off task.
  • ElastiCache Redis for REDIS_URL.
  • Chroma: one Fargate task, EFS mounted at the Chroma data path. CHROMA_HOST / CHROMA_PORT on the API task point at that service’s Cloud Map name.
  • Inject secrets from Secrets Manager. Images from ECR.

Azure scalable

Front Door / App Gateway · Container Apps · Azure Database · Cache · Files

  • Ingress: Application Gateway or Front Door with a generous request timeout for SSE. Disable buffering if the SKU exposes it.
  • Container Apps: UI min replicas ≥ 1; API max replicas = 1 (or session affinity).
  • Azure Database for PostgreSQL Flexible Server; Azure Cache for Redis.
  • Chroma: one Container App revision, Azure Files volume for persistence.
  • Key Vault references for env; ACR for images.

GCP scalable

HTTPS LB · Cloud Run · Cloud SQL · Memorystore · Chroma on GCE

  • Cloud Run for Streamlit and API. Set API max instances = 1 (HITL). Request timeout at the limit; SSE needs a long-lived HTTP connection (consider GKE if Cloud Run request limits are too short for your chats).
  • Cloud SQL PostgreSQL; Memorystore Redis. Use the Cloud SQL Auth Proxy or a private IP from the serverless VPC connector.
  • Chroma on a small GCE VM or a 1-replica GKE Deployment with a Persistent Disk. Cloud Run cannot hold Chroma’s on-disk index reliably across instances.
  • Secret Manager + Artifact Registry.

Hardening and operations

Backups · secrets · upgrades

  • Do not publish Postgres, Redis, or Chroma on a public IP. Compose already omits host ports; keep it that way on VMs. In scalable topologies, security groups / NSGs / firewalls allow only the API (and Chroma only from the API).
  • Single VM backups: EBS / Azure disk / Persistent Disk snapshots, plus occasional docker compose exec postgres pg_dump. Snapshot Chroma’s volume too — a Postgres-only restore leaves embeddings missing.
  • Managed Postgres: automated snapshots (RDS, Azure Backup, Cloud SQL). Still back up Chroma separately.
  • Rotate JWT_SECRET only with a planned logout of all sessions. Rotate LLM keys in the same secret store you inject at runtime.
  • LangSmith is optional (LANGCHAIN_TRACING_V2 + LANGCHAIN_API_KEY). Leave it off if traces must not leave the VPC.
  • Upgrade on a VM: git pull then docker compose up --build -d. Volumes persist; Alembic runs when the API container starts.
  • Upgrade on ECS/Cloud Run: push a new image tag, roll the UI first, then the API (single replica). Confirm /health/ready before sending traffic.
Checklist ENVIRONMENT=production · strong DB password · JWT secret · TLS · SG/NSG/firewall locked · no bind mounts · no --reload · API replicas = 1 · Chroma replicas = 1 · live + ready 200 · one SSE chat turn succeeds.
